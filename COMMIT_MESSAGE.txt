refactor(auth,api): implement MSAL singleton pattern and standardize environment variables

## Summary
Refactored authentication and API architecture to improve reliability and maintainability. Implemented singleton pattern for MSAL instance management, standardized environment variable naming conventions, and reorganized API layer structure.

## Changes

### Authentication (src/lib/msal.ts)
- Implemented singleton pattern via `getMsalInstance()` function to prevent multiple MSAL instance creation
- Removed custom logger configuration (now uses browser defaults)
- Simplified MSAL configuration by removing LogLevel imports
- Added `postLogoutRedirectUri` to configuration for proper logout flow

### Axios Integration (src/lib/axios.ts)
- Updated to use `getMsalInstance()` instead of direct MSAL import
- Removed hardcoded 30-second timeout (now handled server-side)
- Enhanced error logging with specific messages for silent vs popup token acquisition failures
- Added warning log when no MSAL accounts found
- Improved error handling with better context for debugging

### Environment Variables
Standardized all MSAL-related environment variables with `VITE_MSAL_*` prefix:
- `VITE_CLIENT_ID` → `VITE_MSAL_CLIENT_ID`
- `VITE_AUTHORITY` → `VITE_MSAL_AUTHORITY`
- `VITE_REDIRECT_URI` → `VITE_MSAL_REDIRECT_URI`
- `VITE_API_SCOPE` → `VITE_MSAL_SCOPE`
- Added `VITE_MSAL_POST_LOGOUT_REDIRECT_URI` for logout flow

### Type Definitions (src/types/index.d.ts)
- Added comprehensive TypeScript interfaces for GRN/e-GTN/e-GRN data structures
- Defined `IPaginatedResponse<T>` for API responses
- Created interfaces for: `IGrn`, `IStore`, `IPurchaseOrder`, `IBuyerParty`, `ISupplier`
- Added line item interfaces: `IGrnLineItem`, `IPurchaseOrderLineItem`
- Defined `IGrnDetail` for detailed GRN information

### API Layer Restructuring
- Created new `src/lib/api/` directory for centralized API hooks
- Organized API utilities separate from route-level API functions
- Improved code organization and reusability

### UI Components
- Added `date-range-picker.tsx` for date filtering
- Added `pagination.tsx` for table pagination
- Added `table-skeleton.tsx` for loading states

### Route Structure
- Reorganized stock movement routes with dynamic e-GTN number parameter
- Added new GRN detail route structure under `src/routes/_protected/direct-supply/egrn-report/grn/`
- Enhanced e-GRN creation flow with better parameter handling

### Removed
- Deleted old API utility files: `src/utils/api/auth.ts`, `src/utils/api/egrn.ts`, `src/utils/api/transfers.ts`
- Removed empty `src/utils/api/index.ts`

## Benefits

1. **Reliability**: Singleton pattern prevents race conditions in MSAL initialization
2. **Maintainability**: Standardized environment variable naming improves clarity
3. **Debugging**: Enhanced logging helps identify authentication issues faster
4. **Scalability**: Reorganized API layer supports easier feature additions
5. **Type Safety**: Comprehensive type definitions improve development experience

## Breaking Changes

⚠️ **IMPORTANT**: Environment variable names have changed. Update your `.env` file:

**Old format:**
```env
VITE_CLIENT_ID=...
VITE_AUTHORITY=...
VITE_REDIRECT_URI=...
VITE_API_SCOPE=...
```

**New format:**
```env
VITE_MSAL_CLIENT_ID=...
VITE_MSAL_AUTHORITY=...
VITE_MSAL_REDIRECT_URI=...
VITE_MSAL_POST_LOGOUT_REDIRECT_URI=...
VITE_MSAL_SCOPE=...
VITE_API_BASE_URL=...
```

## Migration Guide

If upgrading from previous version:
1. Update `.env` file with new environment variable names
2. No code changes needed in components - MSAL usage remains the same
3. Ensure `VITE_MSAL_POST_LOGOUT_REDIRECT_URI` is configured for proper logout
